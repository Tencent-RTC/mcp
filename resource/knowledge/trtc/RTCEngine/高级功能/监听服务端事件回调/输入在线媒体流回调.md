The server-side push online media stream callback supports notifying your server of push online media stream events generated using the [Push online media stream](https://www.tencentcloud.com/document/product/647/57835) REST API via HTTP/HTTPS requests. You can provide Tencent Cloud with the relevant configuration information to enable this service.

## Configuration information

TRTC TRTC Console supports self-configured callback information. Once configured, you can receive event callback notifications. For detailed instructions, please see Callback Configuration.

> **Note:**
> You need to prepare the following information in advance:
> 
> - **Required**: the HTTP/HTTPS server address to receive callback notifications.
> - **Optional**: The key for calculating the signature, which is a key of up to 32 characters defined by you, consisting of uppercase and lowercase letters and numbers.

## Timeout Retry

If the Event Callback Server does not receive a response from your server within 5 seconds after sending a Message Notification, it is considered a Notification Failure. After the first failure, an immediate retry is attempted. Subsequent retries will occur at 10-second intervals until the Message Retention Time exceeds 1 minute, after which no further retries will be made.

## Format of the Event Callback Message

Event callback messages are dispatched to your server via HTTP/HTTPS POST requests, in which:
- **Character Encoding Format**: UTF-8.

- **Request**: The body is in JSON format.

- **Response**: HTTP STATUS CODE = 200. The server ignores the specific content of the response package. For the sake of a friendly protocol, it is recommended that the customer carry the response content JSON: {"code":0}.

- **Packet Example**: Below is a packet example for the "push online media stream started successfully" event.

   
   
   【JSON】
   ``` json
   {
           "EventGroupId": 7,
           "EventType":    701,
           "CallbackMsTs":   1701937900012,
           "EventInfo":    {
                   "EventMsTs": 1701937900013,
                   "TaskId":"xx",
                   "Status":0
           }
   }
   ```

|Field name|Value|Meaning|
|---------|---------|---------|
|EVENT_TYPE_STREAM_INGEST_START|701|Push online media stream start|
|EVENT_TYPE_STREAM_INGEST_STOP|702|Push online media stream stop|

### Definition of event information when the event type is (EVENT_TYPE_STREAM_INGEST_START 701):

|Field name|Type|Meaning|
|---------|---------|---------|
|EventMsTs|String|The Unix timestamp of when the event occurred, in milliseconds|
|TaskId|String|Push online media stream task ID|
|Status|Number|Push online media stream start status|

#### Push Online Media Stream Start Status

|Field name|Value|Meaning|Callback Frequency|
|---------|---------|---------|---------|
|STATUS_START_SUCCESS|0|Push online media stream start success|Callback once upon success|
|STATUS_START_FAILURE|1|Push online media stream start failed|Callback once upon failure|
|STATUS_START_AGAIN|2|Push online media stream restart|Retry at 0, 1, 3 seconds. Callback during retry|

#### Push Online Media Stream Status Recommended Handling
| Status | Handling Method |
| --- | --- |
| STATUS_START_SUCCESS | Indicates success, no action needed. |
| STATUS_START_FAILURE | If you receive three push online media stream failed statuses, please check the source URL and restart the  push online media stream. |
| STATUS_START_AGAIN | - Received within 1 minute of starting the  push online media stream: indicates URL connection failed or RTMP push streaming failed. The system automatically triggers a retry. If the final attempt fails, please check if the URL is properly connected<br>- Received after 1 minute of starting the  push online media stream: it may be due to source stream or background network fluctuation triggering a restart. No action needed. |

#### Basic Callback Transfer Example
- **Failed to push online media stream/Push online media stream restart/Push online media stream start success event transition**`STATUS_START_FAILURE` -> `STATUS_START_AGAIN` -> `STATUS_START_SUCCESS`

   > **Note:**
   > 
   > Push online media stream callback may arrive at your callback server out of sequence. You need to sort events based on EventMsTs in EventInfo. If you only care about the latest status of the URL, you can ignore subsequent expired events.
   >

## Computing a signature

Signatures are calculated using the HMAC SHA256 encryption algorithm. After your event callback server receives the callback message, it calculates the signature in the same manner. If they match, it confirms that it is an event callback from Tencent's Real-Time Communication, and not a falsification. The signature calculation is as illustrated below:
``` json
// In the signature 'Sign' calculation formula, the 'key' is the encryption key used for calculating the signature 'Sign'.
Sign = base64(hmacsha256(key, body))
```

>  Body refers to the original package body of the callback request received by you, avoid any transformations, as illustrated below:

func hmacsha256(data string, key string) string {
	h := hmac.New(sha256.New, []byte(key))
	h.Write([]byte(data))
	return base64.StdEncoding.EncodeToString(h.Sum(nil))
}
