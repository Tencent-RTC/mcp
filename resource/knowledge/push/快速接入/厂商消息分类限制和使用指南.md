## Overview

To improve the end-user push experience and maintain a healthy, sustainable notification ecosystem, manufacturers categorize push messages by content and apply different push limits. This document describes manufacturer channel push limits and message categories.

> **Note:**
> - Only IM-type messages need to be configured as system message or important message types for timely push. Marketing, advertising, and similar pushes do not require timely delivery; reaching the device within a period is enough, so they do not need to be configured as system message types.
> - Do not configure message types arbitrarily. Non-compliant configurations may cause the manufacturer to freeze your account.

## Manufacturer push limits and message categories

### FCM
| Limit dimension | Description |
| --- | --- |
| <strong>Total push volume / quota</strong> | - <strong>App-level limit:</strong>Up to 1,500,000 messages per minute.<br>- <strong>Per-device quota:</strong>Up to 1,000 messages per minute to a single device (exceeding this is treated as abuse). |
| <strong>QPS limit</strong> | The rate limit for pushes through the FCM XMPP server is <strong>400 requests per minute</strong>. Each project allows up to 2,500 concurrent connections. |

For details, see [Message throttling](https://firebase.google.com/docs/cloud-messaging/throttling-and-quotas).

> **Priority notes:**
> 
> Push message Channel ID and category can be set via API or Console certificate settings. The scope differs; API settings take priority over Console settings.
