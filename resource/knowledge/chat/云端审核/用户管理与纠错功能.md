## Terminal User Identification Allowlist Configuration

If you do not need to identify the message content sent or received by specific terminal users, you can set up an allowlist in the Terminal User Identification Allowlist module. Follow these steps:
1. Open the [Chat Console](https://console.trtc.io/chat). From the left navigation bar, select **Chat** > **Cloud Review**, then click the **Review Management** tab.

   

2. In the **End User Review Whitelist Configuration** module, click **Add**.

3. In the popup window, choose the **Review Method**, enter the terminal user ID in **User ID**, and click **Confirm**.

   

4. You can edit the review exclusion method for terminal user IDs you’ve added, or delete individual or multiple allowlist records.

## Muted User Management

If you use the [Global Mute](https://www.tencentcloud.com/zh/document/product/1047/34923) API or mute a user from the violation user list in the Cloud Review Console, you can view recently muted user IDs in this module (up to 10,000 entries). This module also lets you mute or unmute users, view mute records, and perform related actions. Follow these steps:

### Add Muted User
1. Open the [Chat Console](https://console.trtc.io/chat). From the left navigation bar, select **Chat** > **Cloud Review**, then click the **Review Management** tab. Scroll down to the **Muted User Management** module to view recently muted or unmuted user IDs.

   

2. Click **Add Muted User**, enter the user ID you want to mute, then select the mute scenario and duration.

   

### Edit User Mute Status

To update the mute status for a user already listed in the Muted User Management module, click **Edit Mute Status** in the action column.

### Query User Mute Records

To view mute records for a specific user, click **Query Mute Records** in the action column.

## Error Correction

### Feature Overview

The correction feature lets you dynamically optimize content identification strategies, providing a closed-loop system for quickly resolving false positives (“intercepted by mistake”) and proactively blocking missed violations (“missed violations”). This improves identification accuracy and response speed while maintaining business security. Unlike model or algorithm updates, correction rules can be added or removed instantly without redeployment, and changes take effect within seconds—enabling rapid response to sudden public opinion events.

### Applicable Scenarios
- Normal content is mistakenly intercepted (for example, marketing copy triggers sensitive words, or UGC content is blocked due to dialects or new expressions), resulting in business loss or user complaints.

- Violation content is missed because rules are lacking (such as new scam phrases or variant sensitive words), leading to compliance risks or harm to brand reputation.

### Limitations
- The correction feature is best suited for sudden or isolated cases, such as group announcements being mistakenly intercepted. For scenarios requiring semantic understanding or rule-based interception, use Custom Word interception or submit a ticket for model optimization.

- Correction rules typically take effect within about 5 minutes. You can have up to 500 active strategies at the same time.

- Correction rules apply only to exactly matching content. If the content changes, the rule will not apply.

### Usage

The following instructions show how to use the correction feature for both scenarios: normal content mistakenly intercepted, and violation content missed due to lack of rules. You’ll also find guidance for managing correction rules.

#### Correction Operations
1. Open the [Chat Console](https://console.trtc.io/chat). From the left navigation bar, select **Chat** > **Cloud Review**. In **Review Details**, you can view identified content and results. For each item, click **Error** **Correction** and select the appropriate action.

   

2. In the popup window, click **Intercept** or **Release**.

   

3. After you click **Intercept** or **Release**, you can view correction records in Correction Management.

   Example:

   A piece of text was intercepted by the model. Since the business needs to allow it, a correction allow rule was created for that content. Any identical text submitted later will be allowed.

   

#### Error Correction Records
1. Open the [Chat Console](https://console.trtc.io/chat). From the left navigation bar, select **Chat** > **Cloud Review**, then click the **Review Management** tab. In the **Error** **Correction Records** module, you can view correction records.

   

2. In **Correction Records**, you can set a correction strategy to invalid. For active strategies, click **Invalidate** in the action column, then click **Yes** in the popup window to confirm.
