## Overview

This API enables you to send `C2C (one-on-one chat) streaming messages` from one account directly to another. Common use cases include AI assistant replies, delivering large blocks of text character by character, and scenarios requiring real-time content generation and display.
- The API supports message chunking, allowing you to send content in multiple fragments that clients receive incrementally.

- Friendship status (including blacklist) between sender and receiver is not checked, nor is the sender's mute status.

- The `MsgSeq` field for streaming messages is set by the caller, may be duplicated, is not generated by the backend, and is not guaranteed to be globally unique.

   > **Note:**
   > 
   > - **Message Size:**
   > - The maximum size for a single streaming message is **128 KB**. This is the combined total size of all chunks for one streaming message, not the size per chunk.
   > - **Send Rate:**
   > - The maximum rate for chunk continuation requests within the same stream is **5 times per second**. If you exceed this rate, the server returns error code **90315** (Request rate exceeded) and rejects the request.
   > - We recommend aggregating chunks by time window: combine tokens received within every **200 ms** window into a single chunk before sending (to comply with the 5 times/sec limit).
   > - **Stream Termination Rules:**
   > - Active termination: Send a chunk with **IsLast=true** to immediately mark the stream as completed.
   > - Timeout termination: The interval between two consecutive chunks must not exceed **15 seconds**. If a timeout occurs, the server automatically appends a termination chunk with **IsLast=true** to finalize the stream.
   > - Once a stream is terminated, it cannot be resumed. Continuation requests for this stream return error code **90318** (Stream completed, no further chunks accepted). To continue sending content, initiate a new streaming message.

## API Description

### Request URL Example
``` bash
https://xxxxxx/v4/stream_msg/send_c2c_stream_msg?sdkappid=88888888&identifier=admin&usersig=xxx&random=99999999&contenttype=json
```

### Query Parameters

The table below lists only parameters that require modification when calling this API. For additional details, see REST API Overview.
| Parameter | Description |
| --- | --- |
| xxxxxx | Dedicated domain name for the country/region where <code>SDKAppID</code> is located:<br>- China: <code>console.tim.qq.com</code><br>- Singapore: <code>adminapisgp.im.qcloud.com</code><br>- Tokyo: <code>adminapijpn.im.qcloud.com</code><br>- Frankfurt: <code>adminapiger.im.qcloud.com</code><br>- Other data centers are not supported. |
| v4/stream_msg/send_c2c_stream_msg | API endpoint. |
| sdkappid | The <code>SDKAppID</code> assigned by the Chat console when creating the application. |
| identifier | Must be an App administrator account. . |
| usersig | Signature generated by the App administrator account. . |
| random | Enter a random 32-bit unsigned integer, range 0 - 4294967295. |
| contenttype | Request format. Fixed value: <code>json</code>. |

### API Request Rate Limits
- Default API request rate limit: 200 requests per second.

- Trial Edition and Development Edition daily send limit: 1000 messages per day.

### Request Example

#### Sending the Initial Streaming Message Chunk
``` json
{
    "SyncOtherMachine": 1,
    "To_Account": "123456789",
    "MsgSeq": 93847636,
    "MsgRandom": 1287657,
    "MsgBody": [
        {
            "MsgType": "TIMStreamElem",
            "MsgContent": {
                "CompatibleText": "The current version is too low, please upgrade to view streaming messages",
                "Chunks": [
                    {
                        "EventType": "data",
                        "Index": 1,
                        "Markdown": "Hello, this is the first fragment of the streaming message",
                        "IsLast": false
                    }
                ]
            }
        }
    ],
    "CloudCustomData": "your cloud custom data"
}
```

#### Sending Subsequent Streaming Message Chunks
``` json
{
    "SyncOtherMachine": 1,
    "To_Account": "123456789",
    "MsgSeq": 93847636,
    "MsgRandom": 1287657,
    "MsgBody": [
        {
            "MsgType": "TIMStreamElem",
            "MsgContent": {
                "StreamMsgID": "stream_msg_id_from_first_response",
                "Chunks": [
                    {
                        "EventType": "data",
                        "Index": 2,
                        "Markdown": " - Continued content",
                        "IsLast": false
                    },
                    {
                        "EventType": "data",
                        "Index": 3,
                        "Markdown": " - Last chunk",
                        "IsLast": true
                    }
                ]
            }
        }
    ]
}
```

### Request Fields
| Field | Type | Attribute | Description |
| --- | --- | --- | --- |
| From_Account | String | Optional | Sender's <code>UserID</code> (specifies the sending account). |
| To_Account | String | Required | Recipient's <code>UserID</code>. |
| MsgSeq | Integer | Optional | Message sequence number (32-bit unsigned integer), set by the user for message ordering and deduplication. For rules, see the Overview. If not provided, the backend will generate it automatically. |
| MsgRandom | Integer | Required | Message random number (32-bit unsigned integer), used by the backend for deduplication of messages sent within the same second. Fill with a random value. |
| SendMsgControl | Array | Optional | Message sending control options, as a string array, only applied to this message:<br>- <code>NoUnread</code>: This message does not count toward unread messages.<br>- <code>NoLastMsg</code>: This message does not update the conversation list.<br>- <code>WithMuteNotifications</code>: Recipient's notification sound settings for the sender are applied for this message (default not applied).<br>- <code>WithBlackListCheck</code>: Checks blacklist status between sender and recipient.<br>- <code>WithFriendCheck</code>: Checks friendship status between sender and recipient.<br>- <code>WithSpeakingCheck</code>: Checks whether the sender is muted. |
| MsgBody | Array | Required | Message content, must contain a <code>TIMStreamElem</code> type message element. |
| MsgType | String | Required | Streaming messages must be <code>TIMStreamElem</code>. |
| MsgContent | Object | Required | Streaming message content object. See the <code>StreamMsgContent</code> structure below. |
| IsNeedReadReceipt | Integer | Optional | Whether this message requires a read receipt:<br>- 0: Not required.<br>- 1: Required.<br>- Default is 0. |
| OfflinePushInfo | Object | Optional | Offline Push configuration. . |

### StreamMsgContent Field Description

|Field|Type|Attribute|Description|
|---------|---------|---------|---------|
|CompatibleText|String|Optional|For compatibility, set a prompt text. Default: "Current version too low, please upgrade to view streaming messages."|
|StreamMsgID|String|Optional|Not required for the first streaming message. Subsequent streaming messages must include this field (returned in the initial response).|
|Chunks|Array|Required|Streaming message chunk array. See the `StreamChunk` structure below.|

### StreamChunk Field Description
| Field | Type | Attribute | Description |
| --- | --- | --- | --- |
| EventType | String | Required | Chunk type:<br>- <code>data</code>: AI reply streaming content or general data. |
| Index | Integer | Required | Chunk index, starting from 1, strictly increasing. |
| Markdown | String | Required | Streaming Markdown content. |
| IsLast | Boolean | Required | Indicates whether this is the last chunk; the last chunk must have <code>IsLast=true</code>. |

### Response Example
- Normal response (first message chunk):

   ``` json
    {
        "ActionStatus": "OK",
        "ErrorInfo": "",
        "ErrorCode": 0,
        "StreamMsgID": "stream_c2c_1234567890_abcdef",
        "MsgKey": "c2c_msg_key_xxx",      
        "MsgId": "c2c_msg_id_xxx"
    }
   ```
- Error response:

   ``` json
    {
        "ActionStatus": "FAIL",
        "ErrorInfo": "Streaming message format error",
        "ErrorCode": 90300
    }
   ```

### Response Fields
| Field | Type | Description |
| --- | --- | --- |
| ActionStatus | String | Result of request processing:<br>- OK: Success.<br>- FAIL: Failure. |
| ErrorCode | Integer | Error code:<br>- 0: Success.<br>- Non-zero: Failure. |
| ErrorInfo | String | Error message. |
| StreamMsgID | String | Unique identifier for the streaming message, used for subsequent streaming requests. |
| MsgKey | String | Unique key for the message. |
| MsgId | String | Message ID. |

## Error Codes

Unless a network error occurs (such as a 502 error), the HTTP status code returned by this API is always 200. Actual error codes and error messages are provided in the response body as `ErrorCode` and `ErrorInfo`.

For standard error codes (60000 to 79999), see the Error Codes documentation. The following are private error codes for this API:

|Error Code|Description|
|---------|---------|
|90300|Streaming message format error.|
|90306|Failed to parse StreamMsgID.|
|90308|UserSig or A2 is invalid.|
|90309|Internal server error.|
|90310|Failed to parse JSON format.|
|90311|MsgBody format error.|
|90312|MsgBody is not an array type.|
|90314|Chunk index is not continuous.|
|90315|Request frequency exceeded.|
|90316|Chunk already exists (duplicate).|
|90318|Stream completed, no new chunks accepted.|
|90319|Message body size exceeded.|
|90325|App administrator privileges required for request.|
|90326|Sender or receiver UserID is invalid or does not exist. Please check whether the UserID has been imported into Chat.|
