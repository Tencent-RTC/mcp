This document provides a detailed guide on how to use Atomicx's [useRoomState](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#module-RoomState) to manage the full lifecycle of a room, including creating, joining, leaving, and ending a room, as well as handling key room state notifications. The following sequence diagram illustrates the main flow of a room from creation to destruction.

## Feature Overview

[useRoomState](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#module-RoomState) is the core Hook responsible for room management in the Atomicx solution. It encapsulates the complex underlying signaling flow, allowing developers to drive room state through simple reactive data and method calls.
- **Create and join:** Create and join a room via the [createAndJoinRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#createAndJoinRoom) method, or join an existing room via the [joinRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#joinRoom) method.

- **Real-time state synchronization:** The `useRoomState` Hook internally maintains the [currentRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#currentRoom) reactive data, automatically synchronizing information such as the room name, mode, and participant count.

- **Role-based exit mechanism:** Provides clear operation boundaries for different roles. A regular participant can use [leaveRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#leaveRoom) to exit; while the room owner (host) has the [endRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#endRoom) permission and can end the room and destroy its resources with one click.

## **Prerequisites**

The user has completed login authentication via [useLoginState](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#module-LoginState). Please refer to Integration Overview.

## Implementing Room Management

### Step 1: Import useRoomState
``` typescript
import { useRoomState } from 'tuikit-atomicx-vue3/room';

const {
  createAndJoinRoom,
  joinRoom,
  leaveRoom,
  endRoom,
  currentRoom
} = useRoomState();
```

### Step 2: Create a Room

Create a room (room owner): Use [createAndJoinRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#createAndJoinRoom). After a successful call, the user automatically gains room owner permissions.

> It is recommended that the roomId specified when creating a room be generated and delivered by the business backend, to ensure the uniqueness and stability of the room ID across the entire application globally.
>

- **Example 1: A user creates a room**

   ``` typescript
   import { useRoomState } from 'tuikit-atomicx-vue3/room';
   const { createAndJoinRoom } = useRoomState();

   await createAndJoinRoom({
     roomId: 'YOUR_ROOM_ID',    // Specify the room ID, generated by the business backend
   })
   ```
- **Example 2: A user creates a room and specifies the room name**

   ``` typescript
   import { useRoomState } from 'tuikit-atomicx-vue3/room';
   const { createAndJoinRoom } = useRoomState();

   await createAndJoinRoom({
     roomId: 'YOUR_ROOM_ID',    // Specify the room ID, generated by the business backend
     options: {
       roomName: 'My Temporary Room'
     }
   })
   ```
- **Example 3: A user creates a password-protected room**

   ``` typescript
   import { useRoomState } from 'tuikit-atomicx-vue3/room';
   const { createAndJoinRoom } = useRoomState();

   await createAndJoinRoom({
     roomId: 'YOUR_ROOM_ID',    // Specify the room ID, generated by the business backend
     options: {
       roomName: 'My Temporary Room',
       password: '123456',
     }
   })
   ```

   > **Note:**
   >

   > When the creator calls [createAndJoinRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#createAndJoinRoom), they automatically join the room without needing to enter the password.
   >

- **Example 4: A user creates a room and configures member management settings**

   ``` typescript
   import { useRoomState } from 'tuikit-atomicx-vue3/room';
   const { createAndJoinRoom } = useRoomState();

   await createAndJoinRoom({
     roomId: 'YOUR_ROOM_ID',    // Specify the room ID, generated by the business backend
     options: {
       roomName: 'My Temporary Room',
       password: '123456',
       isAllMicrophoneDisabled: true,   // Enable mute-all
       isAllCameraDisabled: true,       // Enable disable-all-cameras
       isAllScreenShareDisabled: true,  // Enable disable-all-screen-sharing
       isAllMessageDisabled: true,      // Enable disable-all-in-room-messages
     }
   })
   ```

   > **Note:**
   >

   > Member management configuration only applies to regular participants; the room owner and administrators are not restricted. If you need to modify the member management configuration after the room is created or manage individual member permissions separately, please refer to Member Management.
   >

### Step 3: A User Joins an Existing Room

A logged-in user can call [joinRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#joinRoom) to join an existing room. Atomicx only supports a user joining one room at a time.
- **Example 1: A user joins a room**

   ``` typescript
   import { useRoomState } from 'tuikit-atomicx-vue3/room';
   const { joinRoom } = useRoomState();

   await joinRoom({
     roomId: 'YOUR_ROOM_ID',    // Specify the room ID, generated by the business backend
   })
   ```
- **Example 2: A user joins a password-protected room**

   ``` typescript
   import { useRoomState } from 'tuikit-atomicx-vue3/room';
   const { joinRoom } = useRoomState();

   await joinRoom({
     roomId: 'YOUR_ROOM_ID',    // Specify the room ID, generated by the business backend
     password: '123456',
   })
   ```

### Step 4: Update Room Information

The room owner can use [updateRoomInfo](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#updateRoomInfo) to update the room name and password after creating the room.
``` typescript
import { useRoomState } from 'tuikit-atomicx-vue3/room';
const { updateRoomInfo } = useRoomState();

await updateRoomInfo({
  roomId: 'YOUR_ROOM_ID',    // Specify the room ID, generated by the business backend
  options: {
     roomName: 'New Room Name',
     password: '234567',
  },
})
```

> The room owner must be inside the room to call [updateRoomInfo](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#updateRoomInfo). If the room owner has already left the room, they need to rejoin before they can update the room information.
>

### Step 5: Leave a Room

Both the room owner and regular users can call the [leaveRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#leaveRoom) interface to leave a room. The prerequisite for using this interface is that the user has already joined the room via the [createAndJoinRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#createAndJoinRoom) or [joinRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#joinRoom) interface.
``` typescript
import { useRoomState } from 'tuikit-atomicx-vue3/room';
const { leaveRoom } = useRoomState();

await leaveRoom();
```

### Step 6: Destroy a Room

Only the room owner can call the [endRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#endRoom) interface to destroy a room. The prerequisite for using this interface is that the user has created the room via [createAndJoinRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#createAndJoinRoom) or has already obtained the room owner identity.
``` typescript
import { useRoomState } from 'tuikit-atomicx-vue3/room';
const { endRoom } = useRoomState();

await endRoom();
```

> **Note:**
> - If the room owner leaves the room but does not call [endRoom](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#endRoom), the room will continue to exist until the automatic reclamation condition is met (no users for 6 consecutive hours).
> - The room owner can transfer the room owner identity to another user via the [transferOwner](https://web.sdk.qcloud.com/trtc/live/web/doc/en/index.html#transferOwner) interface.

### Step 7: Handling Abnormal Exits

#### Handling the Room Destroyed Event

Regular users can listen to the `RoomEvent.onRoomEnded` event to handle the business interaction for when a room is destroyed.
``` typescript
import { useRoomState, RoomEvent } from 'tuikit-atomicx-vue3/room';
import { TUIMessageBox } from '@tencentcloud/uikit-base-component-vue3';
const { subscribeEvent, unsubscribeEvent } = useRoomState();

function onRoomEnded() {
  TUIMessageBox.alert({
    title: 'Notice',
    content: 'The room owner has dismissed the room',
  });
}

// Listen to RoomEvent when the component is mounted
subscribeEvent(RoomEvent.onRoomEnded, onRoomEnded);
// Cancel the RoomEvent listener when the component is destroyed
unsubscribeEvent(RoomEvent.onRoomEnded, onRoomEnded);
```

#### Handling the User Kicked Out Event

Regular users can listen to the `RoomParticipantEvent.onKickedFromRoom` event to handle the business interaction for when a user is kicked out of the room.
``` typescript
import { useRoomParticipantState, RoomParticipantEvent, KickedOutOfRoomReason } from 'tuikit-atomicx-vue3/room';
import { TUIMessageBox } from '@tencentcloud/uikit-base-component-vue3';

const { subscribeEvent, unsubscribeEvent } = useRoomParticipantState();

function onKickedFromRoom({ reason }: { reason: KickedOutOfRoomReason; message: string }) {
    let notice = '';
    switch (reason) {
      case KickedOutOfRoomReason.KickedByAdmin:
        notice = 'You have been removed from the room by the room owner';
        break;
      case KickedOutOfRoomReason.ReplacedByAnotherDevice:
        notice = 'Your account has logged in on another device';
        break;
      case KickedOutOfRoomReason.KickedByServer:
        notice = 'You have been removed from the room by the server';
        break;
      case KickedOutOfRoomReason.ConnectionTimeout:
        notice = 'Network connection timed out, exiting the room';
        break;
      case KickedOutOfRoomReason.InvalidStatusOnReconnect:
        notice = 'The room has been dismissed or you were removed while offline';
        break;
      case KickedOutOfRoomReason.RoomLimitExceeded:
        notice = 'The room has reached its participant limit and cannot be joined';
        break;
      default:
        notice = 'You have been removed from the room';
        break;
    }
    TUIMessageBox.alert({
      title: 'Notice',
      content: notice,
    });
  }

// Listen to RoomParticipantEvent when the component is mounted
subscribeEvent(RoomParticipantEvent.onKickedFromRoom, onKickedFromRoom);
// Cancel the RoomParticipantEvent listener when the component is destroyed
unsubscribeEvent(RoomParticipantEvent.onKickedFromRoom, onKickedFromRoom);
```

## Advanced Implementation

The current document describes quickly creating and immediately joining a room, which is suitable for instant multi-person audio/video communication scenarios.

However, in real-world business scenarios, we often need to plan ahead: set the room topic, schedule specific start and end times, and invite participants. Participants can receive a reminder before the multi-person audio/video room begins and join on time.

Atomicx provides complete scheduled room capabilities, including:
- **Schedule rooms:** Set the multi-person room time and participant list in advance.

- **Scheduled list**: View and manage all your upcoming multi-person rooms.

- **Join reminders:** Support automatic reminder logic before the start.

## FAQ

### If there are no more users in a room but the room has not been dismissed, will the room exist indefinitely?

When there are no users entering a room for 6 consecutive hours, the backend will attempt to reclaim the room.

### If there are no more users in a room but the room has not been dismissed, will it incur any cost?

A room that has no users but has not been dismissed only occupies the group count of your package; it does not incur minute consumption or additional cost.
